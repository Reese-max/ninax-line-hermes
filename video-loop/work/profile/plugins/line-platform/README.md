# NINAX video delivery

This profile overrides the installed `line-platform` plugin through Hermes' normal plugin discovery. It inherits the native LINE adapter, webhook signature verification, authorization, queueing and ordinary conversation behavior.

The generic platform extension is `run_custom_turn(ctx) -> dict | None` on the adapter class. `TurnRunner.run_sync` calls it after gateway authorization and before creating any agent stream. `None` preserves the ordinary agent route; exceptions propagate without invoking another agent. A handled result carries the normal gateway result fields, including `messages`, `history_offset`, `session_id`, `agent_persisted`, and delivery flags. The platform must own its deadline and cancellation. NINAX uses this to run a bounded video workflow with the installed auxiliary LLM client and no agent tools.

Video work reuses the installed video pipeline, media and per-image caches. `evidence.json` stores source evidence and per-turn checklist/audit/approval records. A separate provider receipt records an accepted billable task immediately so a timeout cannot trigger a duplicate request. Draft streaming and the native slow-answer cache are disabled only for these video turns. The send gate compares the actual native LINE message objects, immutable turn identity, evidence revision and file stamps before sending or recording delivery. A send with uncertain server acceptance is not retried.

Limits per turn: 300 seconds including delivery, up to 3 searches and 3 candidate URLs, one extra single-video metered fetch, and one source-recovery pass with at most two targets. Each source review permits one text revision and two audits. ASR targets are at most 120 seconds; visual targets are at most 30 seconds with three extra frames, up to 64 observations per job. Source-adjacent targets are derived from real evidence IDs. Completed ASR ranges can switch to on-screen text; exhausted methods remain explicit uncertainties. Title similarity does not establish video identity. Ordered visual matching identifies a matching version without asserting creator ownership.

Videos over five minutes or oversized evidence are reviewed in bounded sections. Audited sections are durable; `繼續摘要` retains the original question and resumes work. The final integration is audited against the cited source facts and checked for native LINE truncation. Its ceiling is 60k source characters and 100 requirements; larger results require an attachment path that is not implemented. An unavailable audit produces a limitation/progress notice, never an unaudited new summary. Profile-local `video-settings.json` selects paths; the original deployment remains the fallback when absent. Quality counts, latency and reported token usage are saved to the jobs root without inventing a monetary cost.

Inbound versioning: `line_input_lifecycle.py` keeps a durable per-channel record of every `message`/`messageEdited` webhook — one event receipt per `webhookEventId`, one revision head per `(chat, message)` identity, and one job receipt per accepted revision. The same `webhookEventId` redelivered cannot start work twice. An edit supersedes the previous revision: its job is marked `SUPERSEDED`, any active video run for that message is interrupted, and a completed-but-stale job cannot pass the delivery gate (`send` and `_send_messages` both re-check `is_current` before transport). Delivery receipts persist `DELIVERED` / `UNKNOWN` / `REJECTED_STALE` against the exact `webhookEventId + message id + revision + content hash`; a `UNKNOWN` send keeps an ambiguous-acceptance receipt instead of pretending refund. Receipts survive restarts, so dedupe, the current head and pending deliveries resume from disk. A revision whose job receipt is missing stays resumable by any still-current event, and a ledger-level duplicate still reaches the store, so a crash between the inbound ledger accept and the job receipt cannot strand accepted work. Unreadable receipts are quarantined (`*.corrupt-*`) and the revision head is rebuilt from surviving receipts; a state file from a newer schema still fails closed. `messageEdited` events reuse the native authorization and inbound-ledger envelope before entering the revision store.

Validation: `check_video.py` covers evidence, identity, cache, concurrency, audit coverage and child-process cleanup. `tests/test_line_input_lifecycle.py` covers duplicate redelivery, edit-before/during/after work, out-of-order arrival, restart recovery, cost receipts and the stale-delivery gate. `check_line_video.py` loads the actual modified TurnRunner and profile plugin in a temporary Hermes home, calls the real configured provider, redirects only LINE transport to localhost, and checks final payload/persistence/bypass behavior. Real phone acceptance remains a separate check.
